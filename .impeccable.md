## Design Context

### Users
The platform is used by campus charging station managers, operations staff, maintenance teams, finance reviewers, support staff, and a read-only AI operations assistant. They work in repeated operational shifts, scanning station load, charger health, session timelines, faults, billing exceptions, and command outcomes. Speed, clarity, and auditability matter more than decorative storytelling.

### Brand Personality
Precise, controlled, industrial. The interface should feel like an operations cockpit for energy infrastructure: calm under load, dense enough for repeated work, and explicit about state changes.

### Aesthetic Direction
Use a restrained industrial management-console direction. Prefer sharp geometry, low radius, clear borders, high-contrast status color, tabular numbers, and quiet surfaces. Avoid marketing hero layouts, ornamental gradients, purple/blue AI aesthetics, beige monotony, and visible instructional copy. Design references: BMW-like angular precision for geometry, Airtable-like clarity for dense tables, and a moderated ClickHouse-like high-contrast accent discipline without turning the app into a neon dark landing page.

### Design Principles
- Put operational state first: site load, charger availability, active sessions, faults, and command state should be visible without explanatory text.
- Keep controls compact but touch-safe: icon buttons, segmented controls, filters, and forms must fit desktop operations and mobile checks.
- Do not duplicate visible information or add in-page commentary; labels should name data and actions only.
- Use status color semantically with text or icons, never as the only signal.
- Validate layouts at desktop, tablet, and mobile widths before marking UI work complete.
